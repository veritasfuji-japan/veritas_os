# VERITAS OS クロスVM監査カストディ・リハーサル v0.1（日本語要約）

**実施状況:** 同一Mac/UTM上の2台のUbuntu VMで、開発者が操作したローカル実測。**独立監査ではありません。**  
**実施日:** 2026年11月6日（日本時間）  
**検証コード:** `6c2f5ef264ee1d0de4970228a03653262e6c9663`  
**対象:** 合成データによるローカル監査履歴の継続性。外部イベントや実行権限の真正性は対象外。

## 構成

- **VM-A:** PostgreSQL監査レジストリ、検証器、検証者が指定するCA・TLSホスト名・署名者公開鍵・最低シーケンス。
- **VM-B:** 別OSロールで管理するEd25519署名済みレシート、SQLiteカストディヘッド、読み取り専用HTTPSサービス。
- **照合:** TLS認証 → リモートヘッド → 公開鍵とシーケンス → レシートと署名 → チェックポイント → PostgreSQL履歴。

2台のVMは同一Macを共有します。OSアカウント分離は検証しましたが、物理ホストや管理者・信頼ドメインの独立性は証明していません。

## 実測結果

操作者が保存した再実行JSONの結果として、**7件中7件が期待どおり**でした。

| 条件 | VERITASの判定 | 終了コード |
|---|---|---:|
| 正常な履歴 | `HISTORY_UNCHANGED_UNAUTHENTICATED` | 0 |
| 履歴全件削除 | `INCOMPLETE` | 2 |
| 元の履歴1件を削除し新しい1件を残す | `HISTORY_DIVERGED` | 2 |
| 最低シーケンスを1から2に引き上げる | `REMOTE_HEAD_SEQUENCE_ROLLBACK` | 2 |
| 署名者公開鍵を不一致にする | `REMOTE_SIGNER_PIN_MISMATCH` | 2 |
| レシート署名欄を改変する | `RECEIPT_INVALID` | 2 |
| 改変後の内部ハッシュを再計算する | `CUSTODY_HEAD_MISMATCH` | 2 |

別途、正常な履歴追加で `HISTORY_EXTENDED_UNAUTHENTICATED`、HTTPSサービス停止中に `REMOTE_ANCHOR_UNAVAILABLE`（終了コード2）、再起動後に正常照合への復帰（終了コード0）を観測しました。これらの操作は7件の保存済み再実行JSONとは別です。

## 証拠と制約

原本証拠は非公開のローカル保管です。公開レポートには原本のSHA-256およびマニフェストのSHA-256を掲載し、今後の照合を可能にしていますが、独立した時刻証明・WORM・第三者の証拠保管を意味しません。

今回の署名変更テストは内部整合性／ヘッド一致の段階で拒否されました。**Ed25519署名検証そのものによる拒否**を直接実証したテストとは区別します。SQLiteカストディストアの実ロールバック、独立した最高シーケンスの保持、敵対的な共通管理者、原本イベントの真正性、本番向けの鍵管理はいずれも未検証です。

## 次の検証条件

独立したホスト・管理者での再現、検証者による信頼ピンの独立保管、カストディストアの実ロールバック試験、第三者による生ログ・ハッシュ・証拠連鎖の確認が必要です。
