# NeoMundi RGC v0.2 Real-Observation PoC Runbook

## Purpose

This runbook defines the first real NeoMundi → VERITAS external measurement proof.

The PoC accepts one explicitly bound partner handoff packet, verifies one real NeoMundi-generated signed RGC v0.2 observation, binds the selected Ed25519 verification key to a separately supplied Trusted Public Key Provenance Receipt, seals the measurement behind the existing provider-neutral `ExternalMeasurementEvidence` boundary, and emits reproducible verification artifacts.

It does not create execution authority.

## Boundary

The following invariants remain mandatory:

```text
Measurement != Authority
Advisory != Authorization
Signal Verification != Execution Permission
Within Bounds != VERITAS ALLOW
External Evidence != Governance Decision
Intake Manifest != Trust
Key Fingerprint Correlation != Trust-Channel Authenticity
```

A successful run proves only that:

1. the exact RGC artifact, public JWKS, and Trusted Public Key Provenance Receipt match one intake manifest;
2. the manifest-declared artifact ID, key ID, and signer identity match the supplied RGC artifact;
3. the Ed25519 public key selected by `integrity.key_id` matches the SHA-256 fingerprint recorded in the supplied provenance receipt; and
4. VERITAS independently accepts the signed measurement artifact under an explicit VERITAS-controlled trust policy.

It does not prove production readiness, certification, a customer deployment, permission to execute an external action, the authenticity of the intake handoff channel, or that VERITAS independently established the out-of-band trust channel named by the provenance receipt.

## Required Intake From NeoMundi / Operator

For the first real observation, obtain:

1. One real RGC v0.2 JSON artifact generated by NeoMundi.
2. The public JWKS that contains the Ed25519 key referenced by `integrity.key_id`.
3. A separate Trusted Public Key Provenance Receipt for that public key, conforming to `schemas/trusted_public_key_provenance_receipt.schema.json` and created from an operator/reviewer trust channel rather than from the RGC artifact itself.
4. A NeoMundi Real Observation Intake Manifest conforming to `schemas/neomundi_real_observation_intake_manifest.schema.json`.
5. A stable signer identity in `integrity.signer_identity`.
6. `identity.schema_version = 0.2.0`.
7. A timezone-aware `identity.timestamp`.
8. The measurement and normalizer versions in `provenance`.
9. The expected RGC v0.2 governance boundary with:
   - `authorization_status = not_applicable`
   - `execution_permission_changed = false`

Do not request a private signing key. VERITAS needs public verification material only.

The provenance receipt must record `bundle_internal_key_used = false`. A key copied only from the RGC artifact or another artifact being verified is not accepted as its own trust basis.

## Intake Manifest

The official real-observation CLI requires an intake manifest before provider verification. The manifest binds one handoff packet to:

- the exact RGC artifact file SHA-256;
- the exact public JWKS file SHA-256;
- the exact Trusted Public Key Provenance Receipt file SHA-256;
- expected `identity.request_id`;
- expected `integrity.key_id`;
- expected `integrity.signer_identity`;
- RGC artifact type/version;
- an operator/reviewer handoff reference; and
- a timezone-aware `received_at` audit timestamp.

`received_at` is audit metadata only. It is not treated as trusted UTC and it is not used to establish evidence freshness.

The manifest is correlation metadata. It does not authenticate the partner, prove the handoff channel, establish key trust, or create authority.

## Runner

The repository provides:

```text
scripts/run_neomundi_real_observation_poc.py
```

The hardened external-ingress order is:

```text
real RGC v0.2 artifact
+ operator-supplied public JWKS
+ Trusted Public Key Provenance Receipt
+ Real Observation Intake Manifest
        ↓
require exact packet file hashes + artifact/key/signer identity match
        ↓
select artifact integrity.key_id
        ↓
recompute SHA-256(raw Ed25519 public key bytes)
        ↓
require fingerprint == provenance receipt fingerprint
        ↓
NeoMundiRgcV02Verifier
        ↓
provider verification result
        ↓
ExternalMeasurementTrustPolicy
        ↓
replay-safe generic ExternalMeasurementEvidence boundary
        ↓
VerifiedExternalMeasurementEvidence
        ↓
verification report + evidence manifest
```

No network JWKS lookup is performed.

Both the intake-manifest gate and provenance gate occur before the replay guard consumes the observation.

## Example

```bash
python scripts/run_neomundi_real_observation_poc.py \
  --artifact /secure/inbox/neomundi-rgc-v0.2.json \
  --jwks /secure/inbox/neomundi-public-jwks.json \
  --trusted-key-provenance /secure/inbox/neomundi-key-provenance.json \
  --intake-manifest /secure/inbox/neomundi-intake-manifest.json \
  --replay-state-dir .veritas-poc/neomundi-replay-state \
  --output-dir evidence/neomundi/real-observation-001 \
  --max-age-seconds 3600 \
  --max-future-skew-seconds 60 \
  --allow-no-expiry
```

`--trusted-key-provenance` is mandatory for the real-observation CLI. The runner recomputes the fingerprint from the exact JWKS key selected by `integrity.key_id`; it does not accept a fingerprint supplied by the RGC artifact as a substitute.

`--intake-manifest` is also mandatory. It prevents a valid RGC artifact, JWKS, or provenance receipt from being silently mixed with a different partner handoff packet.

`--allow-no-expiry` is intentionally explicit. NeoMundi RGC v0.2 does not currently provide an `expires_at` field, while the generic VERITAS evidence boundary requires expiry by default.

For a reproducible review run, `--now` may be supplied with a timezone-aware ISO-8601 value:

```bash
--now 2026-09-11T06:00:00+00:00
```

Do not use an arbitrary historical `--now` value to make stale evidence appear fresh. Any review artifact must record the actual validation context.

## Intake Manifest Check

Before key-provenance or provider verification, the CLI validates that:

- the manifest has the exact v1 field set;
- `manifest_version = 1.0`;
- `provider_id = neomundi`;
- `artifact_type = neomundi_rgc`;
- `artifact_version = 0.2.0`;
- the declared artifact, JWKS, and provenance-receipt file SHA-256 values match the exact local files;
- the declared artifact ID matches `identity.request_id`;
- the declared key ID matches `integrity.key_id`;
- the declared signer identity matches `integrity.signer_identity`; and
- `received_at` is timezone-aware.

Representative deterministic intake failures include:

```text
neomundi_poc_intake_artifact_hash_mismatch
neomundi_poc_intake_jwks_hash_mismatch
neomundi_poc_intake_provenance_hash_mismatch
neomundi_poc_intake_artifact_id_mismatch
neomundi_poc_intake_key_id_mismatch
neomundi_poc_intake_signer_identity_mismatch
```

An intake failure stops before provenance verification, provider verification, and replay-state consumption.

## Trusted Key Provenance Check

After intake binding and before provider verification, the CLI validates that:

- the receipt has the exact Trusted Public Key Provenance Receipt v1 field set;
- `receipt_type = trusted_public_key_provenance`;
- `algorithm = Ed25519`;
- `bundle_internal_key_used = false`;
- the trust channel is one of the schema-defined values;
- `received_at` is timezone-aware;
- approval and provenance text fields are non-empty;
- the artifact contains one non-empty `integrity.key_id`;
- the supplied JWKS contains exactly one key with that `kid`;
- that key is public-only `OKP` / `Ed25519` material;
- the decoded public key is exactly 32 bytes; and
- SHA-256 of those raw public-key bytes matches `public_key_fingerprint_sha256` in the receipt.

This check correlates key material with an operator/reviewer provenance record. It does not independently authenticate the human or system that created the receipt, validate a KMS or certificate chain, or prove the named trust channel occurred. Those remain external trust-root responsibilities.

## Durable Replay State

`--replay-state-dir` is required.

The PoC runner creates one durable local marker for each accepted replay key using exclusive file creation. Re-running the same accepted artifact against the same replay-state directory fails with:

```text
external_measurement_replay_detected
```

This local filesystem mechanism is sufficient for the reproducible PoC but is not a distributed production replay service and must not be described as one.

## Outputs

A successful run writes:

```text
verification_report.json
verified_external_measurement_evidence.json
evidence_manifest.json
```

### verification_report.json

Records:

- intake-manifest acceptance metadata;
- provider verification result;
- verifier identity and policy binding;
- generic trust-policy acceptance;
- freshness policy;
- explicit no-expiry posture;
- trusted-key provenance acceptance metadata;
- selected key ID and recomputed public-key fingerprint; and
- claim boundary.

Reviewer-safe intake metadata includes the manifest ID, canonical/file hashes, handoff reference, declared identity binding, and explicit non-trust flags. The report does not turn `received_at` into trusted UTC.

The key-provenance binding does not copy `approved_by`, free-form provenance notes, or the approval reference into reviewer-safe binding metadata.

### verified_external_measurement_evidence.json

Contains the sealed provider-neutral `VerifiedExternalMeasurementEvidence` representation, including:

- normalized evidence;
- evidence hash;
- key ID and algorithm;
- verifier policy hash;
- trust policy hash;
- replay key; and
- verification proof hash.

### evidence_manifest.json

Binds the run to:

- provider and artifact ID;
- RGC artifact version;
- payload hash;
- canonical artifact hash;
- exact input-file SHA-256 when invoked through the CLI;
- canonical and exact-file JWKS hashes;
- canonical and exact-file intake-manifest hashes;
- selected public-key fingerprint;
- canonical and exact-file Trusted Public Key Provenance Receipt hashes;
- verifier policy;
- trust policy;
- evidence hash;
- verification proof hash; and
- output canonical hashes.

The manifest also records explicit non-claims.

## Failure Behavior

The runner fails closed.

Intake-manifest failures stop first, before all trust verification and replay-state consumption.

Trusted-key provenance failures stop after packet correlation but before provider verification and replay-state consumption. Representative deterministic reasons include:

```text
neomundi_poc_provenance_receipt_invalid
neomundi_poc_provenance_bundle_internal_key_forbidden
neomundi_poc_provenance_key_binding_invalid
neomundi_poc_provenance_private_jwk_forbidden
neomundi_poc_provenance_fingerprint_mismatch
```

Provider-specific failures preserve the deterministic NeoMundi reason when available, for example:

```text
neomundi_rgc_payload_hash_mismatch
neomundi_rgc_key_untrusted
neomundi_rgc_signature_invalid
neomundi_rgc_execution_permission_invalid
```

Generic boundary failures remain generic VERITAS evidence failures, for example:

```text
external_measurement_stale
external_measurement_expiry_missing
external_measurement_replay_detected
external_measurement_verifier_binding_mismatch
```

On failure, the CLI writes `verification_report.json` but does not emit a successful sealed-evidence file or success manifest.

## First Real PoC Exit Criteria

The NeoMundi external proof is not closed until all of the following are true:

1. The input is a real NeoMundi-generated signed RGC v0.2 artifact, not a repository fixture.
2. The exact artifact/JWKS/provenance-receipt packet is bound by a preserved intake manifest.
3. The intake manifest identity declarations match the actual RGC artifact.
4. The selected Ed25519 verification key is correlated to a separately supplied Trusted Public Key Provenance Receipt by raw-key SHA-256 fingerprint.
5. The provenance receipt is backed by a real operator/reviewer out-of-band trust process; VERITAS fingerprint correlation alone does not establish that process.
6. VERITAS independently verifies payload identity, key binding, JWS signature, signed claims, semantics, and freshness.
7. Replay protection accepts the artifact only once in the selected PoC replay-state namespace.
8. A `VerifiedExternalMeasurementEvidence` proof is produced.
9. Measurement remains structurally separate from AuthorityEvidence, HumanApproval, and BindAuthorization.
10. VERITAS governance inputs are evaluated independently after the measurement verification step.
11. The later governance result is bound into an auditable receipt / Evidence Packet.
12. The complete run is reproducible and reviewable from preserved artifacts.

## Current Scope

This runner intentionally stops before VERITAS Policy / Authority / Human Approval evaluation.

That separation is deliberate. The first step is to prove that real third-party measurement can cross the verification boundary without becoming authorization. The subsequent PoC step may consume the resulting verified measurement as evidence while VERITAS makes its own governance decision.

The internal `verify_neomundi_real_observation_runtime(...)` seam used by synthetic/non-executing rehearsals remains separate from these external-ingress intake/provenance requirements. The official real-observation CLI is the hardened partner-artifact intake path.

## Non-Goals

This work does not change:

- native v2 authorization;
- credential resolution;
- Bind execution;
- external-effect semantics;
- BindReceipt / Outcome semantics;
- reconciliation;
- crash recovery;
- frozen Decision-to-Effect architecture; or
- RCC / REVAS behavior.

It also does not include any real NeoMundi observation or key material in the repository. Neither an intake manifest nor a provenance receipt proves the external handoff/trust channel is authentic by itself.
